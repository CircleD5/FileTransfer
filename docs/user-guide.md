## 0. クイックスタート（忙しい人向け）

まずはこのページだけ読めば使えます。詳しい動きは、各章を参照してください。

### 処理種別とモードの選び方

| 処理種別 | モード | 用途 |
|---|---|---|
| コピー | 親フォルダを含めずに転送 | フォルダの**中身**を、別のフォルダに入れる（テストデータの入れ替えなど） |
| コピー | フォルダごと転送 | フォルダを**丸ごと**、別のフォルダの中に複製する |
| 移動 | 親フォルダを含めずに転送 | フォルダの**中身**だけを、別のフォルダへ移す（元のフォルダは消える） |
| 移動 | フォルダごと転送 | フォルダの置き場所を変える（元の場所からはなくなる） |
| 削除 | 丸ごと削除 | フォルダを中身ごと消す |
| 削除 | 親フォルダのみ残す | フォルダの中身を全部消し、空のフォルダだけ残す |
| 削除 | ファイルのみ削除 | ファイルだけ消し、フォルダの形は残す |
| 配置 | 退避して入れ替え | 本番のアプリを新しい版に入れ替える（旧版は自動で退避される） |
| 退避 | まるごとコピーして退避 | 変更の前に、今の状態を取っておく（例：MSI でインストールする前の業務データ） |
| 復元 | 退避から戻す | 配置・退避の前の状態に戻す（切り戻し） |

- 転送元が**ファイル**のときは、コピー・移動のモードはどちらでも同じ動きです。
- 配置・退避・復元のモードは1つだけで、処理種別を選ぶと自動で入ります。
- **迷ったら：** 何度でも上書きしてよい作業はコピー・移動・削除、本番の入れ替えや、あとで元に戻す可能性がある作業は配置・退避・復元を使います（違いの詳細は [4章](#4-処理種別の違い一覧と例で比べる)）。

### 基本：ファイルをコピーする

1. `FileTransfer2.exe` を起動する（「設定エラー」が出たら、表示されたファイルと項目を直す）
2. 一覧のいちばん下の空の行で、**処理種別**に「コピー」を選ぶ
3. **転送元**にファイルかフォルダ、**転送先**にコピー先を入れる（「…」で選ぶか、貼り付け）
   - 転送先をフォルダにしたいときは、末尾に `\` を付ける（例：`D:\out\`）。付けないと、その名前のファイルとして保存される
4. **「すべて実行」**を押す。各行のステータスが「完了」になれば成功。失敗した行で止まり、理由が下のログに出る
5. よく使う一覧は**「名前を付けて保存」**しておく。次からは右上のプロファイルで選ぶだけで読み込める

### リリース：退避して配置し、いざとなったら戻す

| 行 | 処理種別 | 転送元 | 転送先 |
|---|---|---|---|
| 1 | 退避 | 業務データのフォルダ（例：`D:\BizAppData`） | 退避先（例：`D:\ReleaseBackup\v1.2.0`） |
| 2 | 配置 | 新しい版（例：`C:\Release\v1.2.0\App`。親フォルダ名がリリース番号になる） | 本番のフォルダ（例：`D:\App`） |

1. 上の一覧を作り、**保存**する（例：`Release_v1.2.0`）
2. **「復元用を作成」**を押す → 元に戻すためのプロファイル `Release_v1.2.0_復元` ができる
3. リリース当日：[実行する前の確認](#5-2-実行する前の確認)（管理者として実行・業務アプリを止める・空き容量）をする → `Release_v1.2.0` を「すべて実行」 → 業務アプリを再開
4. 切り戻すとき：業務アプリを止める → `Release_v1.2.0_復元` を選んで「すべて実行」 → 業務アプリを再開

### これだけは覚えておく

- **上から順に実行し、失敗したら止まる**。残りの行は「未実行」のまま
- **退避・配置・復元は、2回実行しても安全**（2回目は何もしない）。コピー・移動・削除は、もう一度同じ操作をする（上書きする）
- **止めたいときは「中止」**。今の行が終わったところで止まる（実行中は、ほかの操作も終了もできない）
- **触りたくない場所は `forbidden_paths.txt` に書く**。どの処理でも、その場所と中のものは避けて実行する（エラーにはならず、ログに「避けました」と出る。[6章](#6-実行のルール)）
- **退避は空き容量を使う**。退避と `.rolledback` は自動では消えないので、ときどき整理する（[5章](#5-2-実行する前の確認)）
- 困ったら [11章](#11-困ったとき) と、ログ（`LogDir\yyyyMMdd.log`）を見る

## 1. 画面の見方

```
[すべて実行] [中止] [上書き保存] [名前を付けて保存] [復元用を作成]  □自動処理  [プロファイル ▼]  実行中：2 / 5
┌ ⚠ 未保存の変更があります。…            [破棄して読み込む] [キャンセル] ┐ ← 必要なときだけ出る
┌───────────────────────────────────────────────┐
│ 処理種別 │ 転送元 │… │ 転送先 │… │ モード │ 日付付与 │ ステータス │▲│▼│▶│×│
└───────────────────────────────────────────────┘
ログ
```

| 部品 | 働き |
|---|---|
| すべて実行 | 一覧の行を上から順に実行する |
| 中止 | 実行中だけ押せる。**今の行が終わったら**止める（[6章](#6-実行のルール)） |
| 実行中：n / 全件 | 実行中の進み具合（今何行目か）。終わると消える |
| 上書き保存 / 名前を付けて保存 | 一覧をプロファイル（TSV ファイル）に保存する |
| 復元用を作成 | 今開いているプロファイル（退避・配置だけのもの）から、元に戻すためのプロファイルを作る（[5章](#5-5-復元用を作成のルール)） |
| 自動処理 | チェックを入れると、Plan フォルダに置かれた計画ファイルを自動で実行する（[8章](#8-自動処理)） |
| プロファイル | 選んだ瞬間に読み込む（[7章](#7-プロファイル)） |
| 転送元・転送先の「…」 | フォルダを選ぶ画面を開く（直接入力・貼り付けもできる） |
| ▲ ▼ | 行を上下に入れ替える |
| ▶ | その行だけ実行する |
| × | その行を一覧から消す（ファイルは消さない） |

- 転送元・転送先のセルにマウスを置くと、その処理種別での意味が表示されます（例：退避の転送先は「退避先のフォルダ」）。
- 処理種別に合わせて、使わないセルは灰色になり、入力できなくなります。

## 2. 処理種別とモード

処理種別は2つのグループに分かれます。

- **ふだんのファイル操作（コピー・移動・削除）**：テストデータの入れ替えなど。2回実行すると、もう一度同じ操作をする（上書きする）
- **リリース用（配置・退避・復元）**：本番の入れ替えと切り戻し。**2回目は何もしない**（1回目の結果を壊さない）

| 処理種別 | 転送元 | 転送先 | モード | 日付付与 |
|---|---|---|---|---|
| コピー | ファイルかフォルダ | コピー先 | フォルダごと転送 / 親フォルダを含めずに転送 | 使える |
| 移動 | ファイルかフォルダ | 移動先 | フォルダごと転送 / 親フォルダを含めずに転送 | 使える |
| 削除 | ファイルかフォルダ | （使わない） | 丸ごと削除 / 親フォルダのみ残す / ファイルのみ削除 | 使わない |
| 配置 | 新しい版のフォルダ（`…\リリース番号\フォルダ`） | 本番のフォルダ | 退避して入れ替え（1つだけ） | 使わない |
| 退避 | 退避するフォルダ | 退避先のフォルダ | まるごとコピーして退避（1つだけ） | 使わない |
| 復元 | 退避先のフォルダ | 戻す先のフォルダ | 退避から戻す（1つだけ） | 使わない |

- モードの「フォルダごと転送」「親フォルダを含めずに転送」は、**転送元がフォルダのときだけ**意味があります。
- 配置・退避・復元の転送元は、必ずフォルダです。

## 3. コピー・移動・削除の動き

### 3-1. 転送元がファイルのとき：転送先の書き方で動きが変わる

| 転送先の書き方 | 意味 | 例（転送元 `C:\in\a.txt`） | 結果 |
|---|---|---|---|
| 既にあるフォルダ | その中へ入れる | `D:\out`（既にある） | `D:\out\a.txt` |
| `\` で終わる | その中へ入れる（なければ作る） | `D:\new\` | `D:\new\a.txt` |
| それ以外 | **そのファイル名で保存**する | `D:\new\b.txt` | `D:\new\b.txt` |

> 注意：`D:\new`（`\` なし・まだないフォルダ）と書くと、「new」という名前の**ファイル**として保存されます。フォルダに入れたいときは、末尾に `\` を付けてください。

### 3-2. 転送元がフォルダのとき：モードで変わる

転送元 `C:\in\Data`（中身：`a.txt`、`sub\b.txt`）、転送先 `D:\out` の例です。

**フォルダごと転送**：フォルダ自体を転送先の中に作ります。

```
D:\out\
  └ Data\
      ├ a.txt
      └ sub\b.txt
```

**親フォルダを含めずに転送**：フォルダの**中身だけ**を転送先に入れます。

```
D:\out\
  ├ a.txt
  └ sub\b.txt
```

### 3-3. 日付付与

| 場面 | 日付が付く場所 | 例 |
|---|---|---|
| ファイル | ファイル名 | `a_20261011153000.txt` |
| フォルダ＋フォルダごと転送 | フォルダ名 | `Data_20261011153000\` |
| フォルダ＋親フォルダを含めずに転送 | 中の各ファイル名 | `a_20261011153000.txt`、`sub\b_20261011153000.txt` |

同じ名前がすでにあれば、`_1`、`_2` … と連番が付きます。日付を付けた場合は、上書きは起きません。

### 3-4. 上書き・移動のときの注意

- 転送先に同じ名前のファイルがあれば**上書き**します（ログに「上書き」と出ます）。
- **移動**のとき、フォルダの中身を移し終えたら、**転送元のフォルダ自体も消えます**（「親フォルダを含めずに転送」でも同じです）。
- 転送元と転送先が同じファイル、または転送先が転送元のフォルダの中にある場合は、エラーで止まります（元ファイルを守るため）。

### 3-5. 削除

転送元 `D:\Work`（中身：`a.txt`、`sub\b.txt`）の例です。

| モード | 結果 |
|---|---|
| 丸ごと削除 | `D:\Work` ごと消える |
| 親フォルダのみ残す | `D:\Work` は残り、中身は全部消える（空のフォルダになる） |
| ファイルのみ削除 | ファイルだけ消え、フォルダの形は残る（`D:\Work\sub\` は空で残る） |

- 転送元がファイルなら、モードに関係なくそのファイルを消します。
- 読み取り専用のファイルも消します。
- 削除の前に確認は出ません。行の内容をよく確かめてから実行してください。

## 4. 処理種別の違い（一覧と例で比べる）

### 4-1. 一覧で比べる

削除は [3-5](#3-5-削除) を参照してください。コピー・移動の「フォルダごと」「親フォルダ含めず」は、転送元がフォルダのときの違いです。

処理種別は、**転送先に中身がどう入るか**で2つに分けて比べます。

| 表 | 処理種別 | 転送先への入り方 | 見比べるところ |
|---|---|---|---|
| 表1 | コピー（親フォルダ含めず）・移動（親フォルダ含めず）・配置・復元 | 転送先のフォルダに、**中身を直接入れる** | 転送先に**元からあったもの**がどうなるか（上書き／入れ替え／残す） |
| 表2 | コピー（フォルダごと）・移動（フォルダごと）・退避 | 転送先の中に、**フォルダを丸ごと作る** | **転送元**が残るか、作るフォルダの名前 |

#### 表1：転送先のフォルダに、中身を直接入れる

| | コピー<br>親フォルダ含めず | 移動<br>親フォルダ含めず | 配置 | 復元 |
|---|---|---|---|---|
| 主な用途 | フォルダの中身を、別のフォルダに入れる（テストデータの入れ替えなど） | フォルダの中身だけを、別のフォルダへ移す | 本番を新しい版に入れ替える | 配置・退避の前の状態に戻す |
| 実行後の転送元 | 残る | **消える**（中身を移したあと、フォルダ自体も消える） | 残る | 残る（何度でも使える） |
| 実行後の転送先 | 転送元の中身が加わる | 転送元の中身が加わる | 新しい版と同じ構成になる。ただし `deploy_keep.txt` に書いたものは、その場に残る。旧版は `BackupDir\リリース番号\` に退避される | 退避した時の状態に戻る（触らない場所はそのまま）。戻す直前の状態は `〇〇.rolledback_日時` に残る |
| 転送先にある同名のファイル・フォルダ | 上書きする（フォルダは1つにまとまり、中の同名ファイルを上書き） | 同左 | 新しい版のものに入れ替わる（`deploy_keep.txt` に書いたものは本番のまま） | 退避のものに入れ替わる |
| 転送先にあって、転送元にないファイル・フォルダ | 残る | 残る | 消える（退避には残る）。`deploy_keep.txt` に書いたものは残る | 消える（`.rolledback_日時` に残る）。触らない場所はそのまま |
| 後で元に戻せるか | 戻せない（上書きされたファイルは残らない。1行でも混ざると「復元用を作成」できない） | 同左 | 戻せる（復元。「復元用を作成」で作れる）。触らない場所は退避されないので戻らない | 配置し直すか、`.rolledback_日時` から手で戻す（「復元用を作成」の対象外） |

#### 表2：転送先の中に、フォルダを丸ごと作る

| | コピー<br>フォルダごと | 移動<br>フォルダごと | 退避 |
|---|---|---|---|
| 主な用途 | フォルダを別の場所に複製する | フォルダの置き場所を変える | 変更の前に、今の状態を取っておく |
| 実行後の転送元 | 残る | **消える** | 残る（何も変えない） |
| 実行後の転送先 | `転送先\転送元のフォルダ名\` ができ、中身が入る | `転送先\転送元のフォルダ名\` ができ、中身が入る | `転送先\53e1705b0c4c\`（転送元のパスから作った12文字の名前）ができ、転送元がまるごとコピーされる |
| 転送先にある同名のファイル・フォルダ | `転送先\フォルダ名\` がすでにあれば、1つにまとまる（中の同名ファイルは上書き） | 同左 | 関係しない（12文字の名前のフォルダを作るので、ぶつからない）。退避済みなら何もしない |
| 転送先にあって、転送元にないファイル・フォルダ | 残る | 残る | 関係しない（同上） |
| 後で元に戻せるか | 戻せない（上書きされたファイルは残らない。1行でも混ざると「復元用を作成」できない） | 同左 | 戻せる（復元。「復元用を作成」で作れる） |

転送元・転送先に指定するものと、日付付与が使えるかは、[2章](#2-処理種別とモード)の表を見てください。

**迷いやすい組み合わせ**

- **コピー（親フォルダ含めず）と配置**：どちらも新しい版を本番に入れられますが、コピーは古いファイルが残り、本番の設定も上書きされ、元に戻せません。本番の入れ替えには配置を使ってください。
- **移動と退避**：退避は名前から「移す」ように見えますが、実際は**コピー**で、転送元は何も変わりません。
- **コピー（フォルダごと）と退避**：どちらも「フォルダを丸ごとコピーする」点は同じです。退避は、2回実行しても最初の状態を上書きせず、復元でそのまま戻せます。あとで戻す可能性があるなら、退避を使ってください。

### 4-2. 例：同じフォルダに実行すると

どれも「フォルダの中身を別の場所へ写す」点は似ていますが、**元のフォルダと、写した先の扱い**がまったく違います。

#### 前提

```
新しい版：C:\Release\v1.2.0\App\
  ├ App.exe          （新）
  └ settings.config  （初期設定）

本番：    D:\App\
  ├ App.exe          （旧）
  ├ old.dll          （新しい版にはないファイル）
  ├ settings.config  （本番の設定）
  └ Logs\a.log
```

#### ① コピー（親フォルダを含めずに転送）：`C:\Release\v1.2.0\App` → `D:\App`

```
D:\App\
  ├ App.exe          （新）        ← 上書き
  ├ old.dll                         ← 残る（不要なファイルが混ざったまま）
  ├ settings.config  （初期設定）  ← 上書きされ、本番の設定が消える
  └ Logs\a.log
旧版はどこにも残らない
```

#### ② 退避：`D:\App` → `D:\ReleaseBackup\v1.2.0`

```
D:\App\                             ← 何も変わらない
D:\ReleaseBackup\v1.2.0\53e1705b0c4c\ ← 今の D:\App をまるごとコピー（名前は付録）
  ├ App.exe（旧）, old.dll, settings.config（本番の設定）, Logs\a.log
```

#### ③ 配置：`C:\Release\v1.2.0\App` → `D:\App`（`deploy_keep.txt` に `D:\App\settings.config` と `D:\App\Logs` を指定）

```
D:\App\
  ├ App.exe          （新）
  ├ settings.config  （本番の設定）← deploy_keep.txt に書いたので、その場に残る（動かさない）
  └ Logs\a.log                     ← 同上
  （old.dll は消える：新しい版と同じ構成になる）
BackupDir\v1.2.0\53e1705b0c4c\      ← 旧版がまるごと残る（切り戻しに使える）
```

#### ④ 移動（親フォルダを含めずに転送）：`C:\Release\v1.2.0\App` → `D:\App`

```
D:\App\                             ← ①のコピーと同じ結果（上書き・old.dll は残る・本番の設定は消える）
C:\Release\v1.2.0\App\              ← 消える（新しい版がもう手元に残らない）
```

#### ⑤ 復元：`BackupDir\v1.2.0` → `D:\App`（③の配置を取り消す）

```
D:\App\                             ← 配置の前の状態（App.exe 旧, old.dll, 本番の設定, Logs）に戻る
BackupDir\v1.2.0\53e1705b0c4c.rolledback_日時\
                                    ← 戻す直前の D:\App（配置後に増えたログなど）が残る
BackupDir\v1.2.0\53e1705b0c4c\      ← 退避はそのまま残る（もう一度配置・復元できる）
```

## 5. リリースと切り戻し

### 5-1. 例と手順

**例：業務データを退避してから、アプリを配置する（`Release_v1.2.0`）**

| 行 | 処理種別 | 転送元 | 転送先 |
|---|---|---|---|
| 1 | 退避 | `D:\BizAppData` | `D:\ReleaseBackup\v1.2.0` |
| 2 | 配置 | `C:\Release\v1.2.0\App` | `D:\App` |

これを保存してから **「復元用を作成」** を押すと、**復元用のプロファイル（`Release_v1.2.0_復元`）が作られます**。行の順番は逆になります。

| 行 | 処理種別 | 転送元 | 転送先 |
|---|---|---|---|
| 1 | 復元 | `BackupDir\v1.2.0` | `D:\App` |
| 2 | 復元 | `D:\ReleaseBackup\v1.2.0` | `D:\BizAppData` |

| | 作業 |
|---|---|
| 準備 | `Release_v1.2.0` を作って保存し、「復元用を作成」で `Release_v1.2.0_復元` を作っておく（拠点へ持って行く前に） |
| リリース | ① [実行する前の確認](#5-2-実行する前の確認)をする（業務アプリを止める） → ② `Release_v1.2.0` を「すべて実行」 → ③ 必要なら MSI で新しい版をインストール → ④ 業務アプリを再開 |
| 切り戻し | ① 業務アプリを止める → ② 必要なら前の版の MSI を入れ直す → ③ `Release_v1.2.0_復元` を「すべて実行」 → ④ 業務アプリを再開 |

- 配置の転送元は `…\リリース番号\配置するフォルダ` の形にします（例：`C:\Release\v1.2.0\App`）。**親フォルダの名前（`v1.2.0`）がリリース番号**になり、配置の退避は `BackupDir\リリース番号\` に作られます。

### 5-2. 実行する前の確認

| 確認すること | 理由 |
|---|---|
| **管理者として実行**している | 権限のないファイルがあると、本番を変える前に止まる |
| **業務アプリを止めて**いる | 使用中のファイルがあると、本番を変える前に止まる |
| **空き容量**が足りている（下の表） | 退避や配置は、コピーで退避を作るため |
| `BackupDir` と `LogDir` が、**アプリのフォルダの外**にある | アプリのフォルダを消しても、切り戻しに必要な退避と記録が残るように |
| リリースの途中で `forbidden_paths.txt` を**書き換えない** | 退避されていない場所を一覧から外すと、復元でその場所が消える |

**空き容量の目安**

| 処理 | 必要な空き容量（どのドライブに） |
|---|---|
| 退避 | 転送元フォルダの大きさ（退避先のドライブ） |
| 配置 | 本番フォルダの大きさ（`BackupDir` のドライブ。触らない場所は除く）。新しい版は、古いものを消してから置く |
| 復元 | 戻す先フォルダの大きさ（`.rolledback_日時` を作る、退避先のドライブ） |

- 退避と `.rolledback_日時` は**自動では消えません**。リリースのたびにたまるので、リリースが落ち着いたら手で整理してください。
- **容量が足りずに止まっても、取り返しのつかない状態にはなりません**。どこで止まっても、空きを作って同じ行をもう一度実行するか、復元すれば元に戻せます。
  - ただし、配置が「新しい版を置く途中」で止まると、本番は入れ替えの途中の状態になります。**再実行か復元が終わるまで、業務アプリを再開しないでください。**
  - 途中まで作った `〇〇.tmp`（正式な退避になる前のもの）は、再実行のときに片付きますが、それまで容量を使います。手で消してもかまいません。

### 5-3. 残すもの（`deploy_keep.txt`）と触らない場所（`forbidden_paths.txt`）

配置するとき、本番フォルダの中のものは次の3つに分かれます。どちらの一覧も、1行に1つの**絶対パス**で書きます。

| 種類 | 書く場所 | 配置のとき | 退避されるか | 復元のとき | 向いているもの |
|---|---|---|---|---|---|
| （どちらにも書かない） | — | 新しい版に入れ替える | される | 配置前に戻る | exe、dll など |
| 残すもの | `deploy_keep.txt` | その場に残す（動かさない） | **される**（コピー） | 配置前に戻る | 業務データ、ログ、本番用の設定ファイル |
| 触らない場所 | `forbidden_paths.txt` | 一切触らない | **されない** | **触らない** | 重いもの、アクセス権の関係で動かしたくないもの |

```
deploy_keep.txt           forbidden_paths.txt
D:\App\settings.config     D:\App\Runtime
D:\App\Logs
D:\App\Data
```

- 残すものは**動かさない**ので、アクセス権や作成日時は変わりません。
- `deploy_keep.txt` は、**配置先フォルダの中にあるものだけ**が使われます。1つの一覧に、すべての配置先の分をまとめて書けます。何が使われたかは、配置のログに出ます。
- フォルダを書くと、中身ごと対象になります。残すフォルダの中に触らない場所を書くこともできます（例：`D:\App\Data` を残し、`D:\App\Data\Archive` は触らない）。
- 新しい版に同じ名前のものがあっても、本番のものが残ります。ただし、**本番になかった残すもの（初めての配置など）は、新しい版のものが置かれます**。触らない場所には置きません。
- 触らない場所は、配置だけでなく、**どの処理でも触りません**（[6章](#6-実行のルール)）。退避にも入りません。

### 5-4. 退避の行が必要なもの・置く順番

新しい版を置くときは、**配置だけで十分です**（配置が自分で本番を退避します）。同じフォルダを「退避」してから「配置」すると、退避が2回作られ、容量を2倍使います。

**退避の行が必要なのは、配置先の外にあって、リリースで変わるかもしれないもの**です（例：MSI のインストールで書き換わる業務データ）。

- 配置先の中のもの（`D:\App` の中のログや設定など）は、**配置が自分で退避する**ので、別に退避の行を置く必要はありません。
- ただし、触らない場所は退避されません（復元しても戻りません）。戻したいものは `deploy_keep.txt` に書いてください。

**退避の行は、その対象を変える操作（配置・MSI のインストールなど）より前に置きます。**

- 後ろに置いても、「復元用を作成」で作った計画で元に戻すことはできます（行を逆の順番で戻すため）。
- ただし、その退避の中身はリリース**後**の状態になります。退避から一部のデータだけを手で取り出したいときに、リリース前のものが取り出せません。

### 5-5. 「復元用を作成」のルール

- **保存してある内容から作ります**。プロファイルを開いていないときや、未保存の変更があるときは作らず、「先にプロファイルを保存してください」と表示します。
- プロファイルが**退避と配置だけ**でできていて、入力エラーがないときだけ作れます。コピー・移動・削除が1行でも混ざっていると作れません（元に戻せない操作があるため）。
- 保存先は `プロファイル名_復元.tsv` です。すでにあれば上書きします。
- **自動では作り直しません**。リリース用を直したら、「復元用を作成」をもう一度押してください（保存し直したときに、ログで知らせます）。

### 5-6. 2回実行したとき・途中で止まったとき

| 場面 | どうなるか |
|---|---|
| 退避・配置・復元を2回実行した | 2回目は何もしない（「退避済み」「適用済み」「復元済み」とログに出る）。リリース後に増えたデータや、配置後のログが上書きされることはない |
| 途中で止まった（容量不足、使用中のファイル、電源断など） | 原因を取り除いて、**同じ行をもう一度実行**すれば正しい結果になる。退避（復元なら `.rolledback`）を作り終えるまで、本番には手を付けないので、どこで止まっても退避はそろっている |

詳しい手順と、止まった場所ごとの動きは [付録](#付録-配置退避復元の仕組み) にあります。

## 6. 実行のルール

- 一覧の行を**上から順に**実行します。
- 入力エラーや失敗があった行で**止まり**、その行は「エラー」、残りの行は「未実行」になります。理由はログに出ます。
- **「中止」**を押すと、**今実行している行が終わってから**止まります（行の途中では止まりません）。次の行から後は「未実行」になります。
  - 止まった後の状態は、失敗で止まったときと同じです。直してから、もう一度「すべて実行」できます（配置・退避・復元は、終わった行をもう一度実行しても何もしません）。
  - 1つの行が長い場合（大きな業務データの退避など）は、その行が終わるまで待つことになります。
  - 「中止」を2回押しても、止めている途中で「すべて実行」を押しても、何も起きません。
- 実行中は、「中止」以外の画面の操作も、アプリの終了もできません。
- 入力エラーになるもの：処理種別が選ばれていない／転送元が空／転送先が空（削除以外）／モードが処理種別に合っていない／配置・退避・復元で日付付与をオンにしている。
- パスの前後の `"` は自動で取り除きます（エクスプローラーの「パスのコピー」をそのまま貼り付けられます）。
- 相対パスは、**アプリ（exe）のフォルダ**から見た場所として扱います。

**触らない場所（`forbidden_paths.txt`）**

- 書いた場所と、その中のものは、**どの処理でも触りません**（読む・書く・移動・削除のどれもしません）。
- エラーにはならず、その場所だけを避けて実行します。避けたことは、ログに場所ごとに1行「触らない場所のため避けました」と出ます。
- 転送元・転送先そのものが触らない場所なら、何もせずに「完了」になります（ログには出ます）。
- 例：`C:\Windows` を書くと、`C:\Windows\Temp` へのコピーも、`C:\` の中身の削除での `C:\Windows` も避けられます。
- 移動で避けたものは、転送元に残ります（転送元のフォルダも残ります）。
- `C:\` のようにドライブごと書くと、そのドライブでは何もできなくなります。できるだけ、触りたくないフォルダに絞って書いてください。

## 7. プロファイル

一覧の内容を保存したファイル（TSV）です。`ProfilesDir` のフォルダに保存されます。

- **読み込み**：コンボで選んだ瞬間に読み込みます。「未選択」を選ぶと一覧が空になります。
- **未保存の変更があるとき**：コンボの選択は元に戻り、一覧の上に黄色い帯が出ます。「破棄して読み込む」で読み込み、「キャンセル」で帯を消します。帯が出ている間も編集や保存はできます。
- **起動時の読み込み**：`settings.config` の `DefaultProfile` に名前を書くと、起動時にそのプロファイルを読み込みます（実行はしません）。
- **保存**：「上書き保存」は今開いているプロファイルに、「名前を付けて保存」は新しい名前で保存します。未選択のときに「上書き保存」を押すと、「名前を付けて保存」と同じ動きになります。
- **ホイール**：コンボの上でホイールを回しても、選択は変わりません。

TSV の形式（1行に1件、タブ区切り）：

```
処理種別	転送元	転送先	モード	日付付与
Copy	C:\in\a.txt	D:\out\	FolderAsIs	False
Backup	D:\BizAppData	D:\ReleaseBackup\v1.2.0	BackupCopy	False
```

処理種別とモードは英語の名前で書きます。

| 処理種別 | 名前 | モードの名前 |
|---|---|---|
| コピー・移動 | `Copy`・`Move` | `FolderAsIs`（フォルダごと転送）、`ExtractContents`（親フォルダを含めずに転送） |
| 削除 | `Delete` | `DeleteAll`、`DeleteKeepParent`、`DeleteFilesOnly` |
| 配置・退避・復元 | `Deploy`・`Backup`・`Restore` | `DeployReplace`・`BackupCopy`・`RestoreReplace` |

## 8. 自動処理

「自動処理」にチェックを入れると、`AutoRunPlanDir` のフォルダを決まった間隔（`AutoRunIntervalMs`）で確認し、置かれた計画ファイル（プロファイルと同じ TSV）を実行します。

| 結果 | 計画ファイルの行き先 |
|---|---|
| 全部成功 | `AutoRunDoneDir` へ移す |
| 失敗 | `AutoRunErrorDir` へ移す |
| 「中止」を押した | `AutoRunErrorDir` へ移し（最後まで終わっていないため）、**自動処理も止める**（チェックが外れる）。ほかの計画ファイルも実行しない |
| どちらにも移せない | 自動処理を止める（同じ計画を何度も実行しないため） |

- 自動処理は一覧を使いません。画面で編集中の内容には影響しません。
- 書き込み中（ほかのプログラムが開いている）の計画ファイルは、次の機会に回します。
- 起動したときは、毎回チェックが外れた状態で始まります。

## 9. 設定ファイル

設定ファイルや項目が欠けていたり値が正しくなかったりすると、「設定エラー」を表示して**起動しません**。プログラム側に既定値はありません。

| ファイル | 内容 |
|---|---|
| `settings.config` | 動作設定（下の表）と、ログの設定。.NET 標準の設定ファイル（XML）の形式 |
| `messages.json` | 画面やログの文言。項目が欠けていると起動しない。**`settings.config` と同じフォルダに置く** |
| `forbidden_paths.txt` | どの処理でも触らない場所（1行に1つの絶対パス。[6章](#6-実行のルール)） |
| `deploy_keep.txt` | 配置のときに本番に残し、退避もするもの（1行に1つの絶対パス。[5-3](#5-3-残すものdeploy_keeptxtと触らない場所forbidden_pathstxt)） |

`settings.config` の書き方（`<fileTransfer>` の中に `項目名="値"` で書く）：

```xml
<fileTransfer
  AutoRunIntervalMs="30000"
  BackupDir="C:\FileTransfer2Data\Backup"
  DefaultProfile=""
  ... />
```

- パスはそのまま書けます（`\` を重ねる必要はありません）。ただし `&` は `&amp;` と書きます。
- 項目名は大文字・小文字を区別します。知らない項目名（書き間違い）があるとエラーになります。
- 誤りがあると、ファイル名と**行番号**つきで表示されます。誤りは**1つずつ**表示されるので、直したらもう一度起動してください。
- `<configSections>` と `<log4net>` の部分は、通常は変更しません（`<log4net>` はログの書式などの設定です）。
- `forbidden_paths.txt` と `deploy_keep.txt` に相対パスが書かれていると、起動時に「設定エラー」になります。

`<fileTransfer>` の項目：

| 項目 | 内容 |
|---|---|
| `AutoRunIntervalMs` | 自動処理の確認間隔（ミリ秒、1以上） |
| `RowDelayMs` | 行と行の間の待ち時間（ミリ秒、0以上） |
| `AutoRunPlanDir` / `AutoRunDoneDir` / `AutoRunErrorDir` | 自動処理の計画ファイルを置く場所／成功したら移す先／失敗したら移す先 |
| `ProfilesDir` | プロファイルの保存先 |
| `DefaultProfile` | 起動時に読み込むプロファイル名。**空（`""`）でもよいが、項目は必須** |
| `LogDir` | ログの出力先（アプリのフォルダの外にする） |
| `LogRetentionDays` | 日付ごとのログを残す日数（0 なら消さない） |
| `ForbiddenPathsFile` / `DeployKeepFile` | 各ファイルの場所 |
| `BackupDir` | 配置の退避先（アプリのフォルダの外にする。短いパスにする） |

- 相対パスは、アプリ（exe）のフォルダ基準です。
- 起動するとき、ログ・プロファイル・自動処理のフォルダがなければ作ります。作れなければ起動しません。
- 別の設定ファイルを使うときは、起動時の引数に渡します（例：`FileTransfer2.exe D:\設定\検証用.config`）。

## 10. ログ

| ファイル | 内容 | 消えるか |
|---|---|---|
| `LogDir\yyyyMMdd.log` | 画面のログと同じ内容（日付ごと）。予期しないエラーは、原因の詳細（どこで起きたか）も残る | `LogRetentionDays` を過ぎたら起動時に削除 |
| `LogDir\deploy_history.log` | 配置の記録（日時・リリース番号・転送元・配置先・実行者） | 消えない |

- 実行を始めるたびに、「実行者：ユーザー名（PC：PC名）」が記録されます。
- 日付ごとのログは log4net で書いています。書式（日時・レベル）は `settings.config` の `<log4net>` で変えられます。

## 11. 困ったとき

| 状況 | 対処 |
|---|---|
| 「設定エラー」で起動しない | 表示されたファイルと項目を直す |
| 「パスの一覧ファイルに誤りがあります」 | 表示されたファイル（`forbidden_paths.txt` か `deploy_keep.txt`）の行を、絶対パスに直す |
| 実行したのに、ファイルが変わっていない | ログに「触らない場所のため避けました」が出ていないか確かめる。出ていれば、`forbidden_paths.txt` に書いた場所に当たっている |
| 「転送元・転送先・退避先のフォルダが重なっています」 | 一方がもう一方の中にないか確かめる（例：退避先を、退避するフォルダの中にしている） |
| 「変更できないファイルがあるため、ここで止めます」 | 表示されたファイルを使っているプログラム（業務アプリなど）を止めるか、権限を確かめてから、もう一度実行する。本番はまだ変わっていない |
| 「ディスクの空き容量が不足しています」 | 空きを作ってから、同じ行をもう一度実行する（または復元する）。配置が途中で止まった場合は、終わるまで業務アプリを再開しない（[5-2](#5-2-実行する前の確認)） |
| 「戻す元の退避が見つかりません」 | 復元の転送元が、退避や配置で使った退避先と同じか確かめる。どのフォルダの退避かは `〇〇.path` で分かる |
| 「退避や復元で作るパスが長すぎるため、実行しません」 | 退避先（`BackupDir` や退避の転送先）を、`D:\BK` のような短いパスにする（[付録](#a-2-パスの長さの事前チェック)） |
| 「退避の名前が、別のフォルダの退避とぶつかっています」 | ほぼ起きない（12文字の名前が偶然一致した）。退避先を別のフォルダにする |
| 配置をやり直したい | `.done` だけを消すと、配置後に増えたログなどが退避の古いもので戻される。復元してから配置し直すのが安全 |
| 退避がたまってきた | 自動では消えない。リリースが落ち着いたら手で整理する |
| データベースを退避したい | 必ずデータベースを止めてから実行する（動いたままコピーすると、壊れた状態で退避される） |

---

## 付録. 配置・退避・復元の仕組み

ふだん使うときは読まなくてかまいません。トラブルの調査や、動きを詳しく知りたいときに読んでください。

### A-1. 退避先の名前の付け方

退避先のフォルダの中に、**対象フォルダのパスから作った12文字の名前（ハッシュ）**のフォルダを作ります。

| 対象フォルダ | 退避の名前 |
|---|---|
| `D:\App` | `53e1705b0c4c` |
| `D:\BizAppData` | `75d6f3c75478` |

- 同じパスからは、必ず同じ名前になります（大文字・小文字や、末尾の `\` の違いは同じとみなします）。そのため、退避や配置で作った退避を、復元でそのまま戻せます。
- 対象フォルダのパスが深くても、名前はいつも12文字です（退避のパスが長くなりすぎないように）。

```
退避先\
  ├ 53e1705b0c4c\                     … 退避（リリース前の状態）。一度作ったら上書きしない
  ├ 53e1705b0c4c.path                 … どのフォルダの退避か（中身：D:\App）
  ├ 53e1705b0c4c.done                 … 配置が終わった印
  ├ 53e1705b0c4c.restored             … 復元が終わった印
  └ 53e1705b0c4c.rolledback_日時\      … 復元する直前の状態
```

### A-2. パスの長さの事前チェック

Windows では、パスの長さに上限があります（ファイルは259文字、フォルダは247文字）。退避のパスは「退避先＋12文字の名前＋元のフォルダの中のパス」になるので、退避先が長い場所だと、元より長くなることがあります。

そこで、配置・退避・復元は、**何かを変える前に**、作ることになるパスが上限に収まるかを確かめます。収まらなければ、何も変えずにエラーで止まり、いちばん長いパスと、何文字超えるかを表示します。

- 計算には、いちばん長くなる名前（復元のときの `〇〇.rolledback_日時`）を使います。配置や退避のときに通っても、あとの復元で止まって**切り戻せなくなる**ことがないようにするためです。
- 配置では、今の本番フォルダに加えて、**新しい版の中身**も確かめます（復元するとき、新しい版が「戻す直前の状態」として退避されるため）。

### A-3. 配置の手順

| 順番 | すること |
|---|---|
| 1 | 配置済みの印（`.done`）があれば、**何もせずに終わる** |
| 2 | 本番フォルダを退避へ**コピー**する（触らない場所は除く）。すでに退避があれば、退避し直さない（旧版を守るため）。**ここまで本番は変えない** |
| 3 | 消す予定のファイルを開いてみて、使用中のものや、権限がなくて消せないものがないかを確かめる。あれば、本番を変えずに止まる |
| 4 | 残すもの・触らない場所以外を消して、新しい版を置く |
| 5 | 配置済みの印を書き、`deploy_history.log` に記録する |

### A-4. 退避

- 転送元をまるごと**コピー**します（触らない場所は除く）。元のフォルダはそのまま残ります。
- 退避がすでにあれば、何もしません（最初の退避＝リリース前の状態を上書きしないため）。
- `deploy_keep.txt` は配置だけで使います（退避には関係しません）。

### A-5. 復元の手順

転送元には**退避先のフォルダ**を指定します（退避の転送先、配置なら `BackupDir\リリース番号`）。

| 順番 | すること |
|---|---|
| 1 | 復元済みの印（`.restored`）があれば、何もせずに終わる |
| 2 | 今の状態を `〇〇.rolledback_日時` に**コピー**する（触らない場所は除く）。**ここまで本番は変えない** |
| 3 | 消す予定のファイルを開いてみて、使用中のものや、権限がなくて消せないものがないかを確かめる。あれば、本番を変えずに止まる |
| 4 | 今の中身を消して、退避を元の場所へコピーする（触らない場所はそのまま。退避そのものは残る） |
| 5 | 配置済みの印を消し、復元済みの印を書く |

復元すると配置済みの印が消えるので、**もう一度配置できます**。配置し直すと復元済みの印が消えるので、**もう一度復元もできます**。

### A-6. 途中で止まったとき

| 止まった場所 | もう一度実行すると |
|---|---|
| 配置・退避：退避のコピーの途中 | `〇〇.tmp` に途中までコピーされているだけで、正式な退避はまだない（本番も変わっていない）。`.tmp` を消してコピーし直す |
| 配置・復元：使用中・権限がないファイルで止まった | 本番は変わっていない。原因を取り除いてから実行する |
| 配置：新しい版を置く途中 | 置きかけの新しい版を消して、置き直す（旧版は退避にある。残すものはその場にある）。復元して配置の前に戻すこともできる |
| 復元：戻す直前の状態のコピーの途中 | `〇〇.rolledback.tmp` を消して、コピーし直す（本番は変わっていない） |
| 復元：戻す途中 | 置きかけの状態をもう一度 `.rolledback_日時` にコピーして、戻し直す（最初の `.rolledback_日時` も残る） |

- コピーは、いったん `〇〇.tmp` という名前で作り、**最後までコピーできてから**正式な名前に変えます。途中で止まったり、PC の電源が落ちたりしても、「退避済み」と誤解されることはありません。
- 容量不足で止まった場合も同じです。どの場所で止まっても、空きを作ってから再実行するか、復元すれば元に戻せることを、テストで確かめています。
